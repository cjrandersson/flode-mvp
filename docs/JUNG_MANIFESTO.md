# JUNG Manifesto

**Status:** Approved product and behavioural authority  
**Branch:** `max-msp`  
**Approved by:** CJ  
**Date:** 2026-09-29

- **The master clock owns time. JUNG never does.**
- **Controlled instability, not chaos.**
- JUNG may change **what happens**, but must never allow the groove to drift away from **when it happens**.
- Prefer a few **musically meaningful tensions** — *stable ↔ restless, restraint ↔ agitation* — over dozens of exposed probability controls.
- PODs may have different personalities, but should not become six independent probability-programming systems.
- Avoid recursive randomness: **one decision → one bounded action → return home.**
- Every disruption must retain a clear path back to the original phrase and timing.
- If a mode or parameter adds complexity without adding recognizable musical character, **remove it**.
- The goal: **flöde~ should sound like it might fall apart while remaining mathematically locked to the music.**

## Design authority

This manifesto defines the intended musical behaviour of JUNG. Technical architecture and implementation must preserve these principles rather than exposing implementation complexity as product complexity.

`JUNG_BRAIN_ARCHITECTURE.md` describes how JUNG may be engineered; this manifesto defines the behavioural constraints that architecture must serve.
